# 1.3.4

CLI conveniences: a hands-off update check, a way to validate follow-up payloads
before you use them, readable tables in narrow terminals, and account addresses
wherever you used to see opaque ids.

## What changed

- **Update check.** The CLI checks GitHub for a newer release at most once an hour
  and caches the result. When a newer version exists, a short "Update available"
  footer appears below command output. The check is best effort and never changes
  a command's result. It runs on by default; set `cli.update_check = false` to
  disable it, or `cli.update_check_interval_s` to change the interval.

- **Follow-up validation.** `downcroc batch validate <path> --followup` checks a
  follow-up payload with the same rules the send commands use. It auto-detects a
  one-shot payload versus a scheduled declaration (a `followup` schedule block),
  so a subject-less message file is validated correctly instead of being rejected
  by campaign validation. Campaign validation now hints at `--followup` when it
  sees a subject-less file that looks like a follow-up payload.

- **Narrow-terminal tables.** When a boxed table cannot fit, the CLI now switches
  to a stacked layout instead of compressing columns and truncating values. Use
  `--stack` to force stacking or `--grid` to force the boxed grid at any width.

- **Account addresses.** `--addresses` is now a global flag, so every command that
  reports an account can show the mailbox address instead of the internal id.
  Machine-readable `--json` output is unchanged and keeps canonical account ids.

- **Docs and scripts.** The follow-up page now leads with the singular/plural
  distinction (`batch followup` adds a step now; `batch followups` manages steps).
  The rendering script's remaining lint findings were fixed.

## What you should see

Run any command as usual. If a new release is out, a small update footer appears;
to stop it, set `cli.update_check = false`. Check a follow-up file with
`downcroc batch validate followup.json --followup` before wiring it into a live
batch. In a narrow window, tables stack their fields instead of clipping values.
Add `--addresses` to a listing to read `you@example.com` in place of `acct_...`.
No configuration change is required; the daemon runs its existing migrations at
startup.
