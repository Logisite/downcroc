# 1.3.1

`1.3.1` is a reliability release. It closes data-loss and silent-failure paths in the vault,
manual sends, account state, provider quota handling, and the send attempt ledger, then makes the
daemon much easier to inspect when something goes wrong.

## Vault and account state

- Unlocking the vault no longer deletes credentials for archived accounts.
- Deleted accounts still have their orphaned vault secrets pruned, with the account ids and
  secret kinds logged.
- `credential_present` is read from the live vault instead of a stored flag.
- Unarchive restores the watcher and validates the credential. If the credential is missing, the
  account becomes `needs_reauth` and stays visible in the API and logs.
- Archived accounts are removed from the SMTP seat plan.

## Credential preflight and capacity

- Vault unlock starts a bounded background credential preflight and returns immediately.
- The preflight checks vault presence, refreshes near-expiry tokens, and uses IMAP login, Gmail
  API profile, or SMTP AUTH depending on the account and its bindings.
- Missing or rejected credentials become `needs_reauth`. Provider outages stay distinct as
  `unavailable`.
- Account and vault responses expose `auth_checked_at`, `auth_status`, `auth_error`, and
  `auth_action`.
- The interactive startup shows a compact credential status strip. `downcroc doctor` reports
  accounts that need reconnect.
- Batch, job, and pending estimates carry `as_of` and `basis` and refresh on every read.

## Manual jobs and sending

- `POST /api/jobs` and `POST /api/jobs/{id}/send` now work end to end.
- Manual creation rejects archived, paused, disconnected, and missing-credential accounts.
- The `manual` batch sentinel no longer reaches the hold lookup as a real batch.
- Batch submission warns about recipients that already appear in recent batches. Use
  `--allow-overlap` or confirm before writing.
- CLI editors now show a visible caret and complete paths with Tab.

## Provider responses and attempts

- SMTP classification reads the enhanced status code and response text, not the numeric reply
  alone. Daily limits and rate limits become `quota_exhausted` with `retry_wait`. Unknown
  recipients fail. Policy blocks fail and cool the binding. Authentication marks reauth.
- Gmail classification reads the error reason plus the `Retry-After` header and JSON body.
- Provider retry times win over the configured minimum cooldown.
- Every reserved send attempt is finalized exactly once, including failures before a transport
  attempt. Startup reconciliation closes stale reservations as `interrupted`.
- Reauth and other non-retryable dispatch failures are logged at warning level with job, account,
  and code.

## Sticky SMTP seat and API fleet

- `dispatch.smtp_seats` is a hard cap on SMTP connections.
- Sticky seats are held until a cap, failure, or batch drain, then move through randomized
  round-robin order.
- Pinned jobs bind the account, not the transport. An unseated API-capable account sends through
  the Gmail API instead of forcing an extra SMTP connection.
- New settings: `dispatch.smtp_seat_sticky`, `dispatch.smtp_seat_max_s`,
  `dispatch.smtp_seat_max_sends`, and `dispatch.smtp_seat_after_batch`.

## Logging and diagnostics

- Policy changes and clears log old and new values, plus the resolved effective limit.
- Vault writes log `vault.saved` with state, not the misleading old lock name.
- Paused service events log actor, reason, and until.
- Token refreshes log whether the refresh token rotated.
- Sends name the account, transport, and binding. `transport.attempt` records each binding tried.
- API requests, auth rejections, daemon recovery, stale locks, and build identity are structured
  events. Sensitive fields are scrubbed at the logging boundary.
- `downcroc logs --addresses` renders account addresses. `--json --addresses` keeps the id and
  adds `account_address`.
- OAuth attempts always end in a terminal event. Watcher stops include cause, host, uid, and
  attempt. Gmail sweeps report skip reasons.

## Follow-up declarations

- Retroactive follow-up declarations are stored in the database, not written back into the
  immutable campaign snapshot.
- Shared declarations carry one body with per-recipient overrides. Payload declarations carry a
  full message per parent recipient.
- Child batches and jobs are threaded to the message that actually reached the recipient.
- Status, remove, and retire are explicit operations. Retire keeps child history.
- Declarations are versioned, unique per parent step, and isolated from other planner failures.

## Upgrade notes

- The database adds account auth state and follow-up declaration tables. The daemon runs the
  migrations at startup.
- No new config is required. Existing account, sending, and follow-up settings keep their
  meaning.
- If you run the daemon as a user service, restart it after upgrading so the new migrations and
  logging middleware load.
- The vault format is unchanged. Keep the master password safe.
