# 1.3.2.post6

Fix for the background Gmail thread id backfill introduced in post5.

## What changed

The backfill worker was reading the token through the raw provider
configuration, which has no OAuth client id. Accounts connected with an
imported client JSON (the `downcroc provider credentials set gmail --client
PATH` flow) were therefore skipped with `backfill.backoff` /
`cause="OAuthNotConfigured"`, leaving all holes unresolved.

Backfill now resolves credentials through the credential resolver, the same
layer used by sending and the auth checks. It overlays each account's imported
OAuth client before refreshing a token, so the worker uses the exact client
you connected with.

## What you should see

After upgrading and restarting the daemon, the backfill pass should log
`backfill.imap_swept` and `backfill.resolved` for accounts with holes, and no
longer log `cause="OAuthNotConfigured"`. Existing thread holes are picked up
automatically; no reconnection or re-import of the client JSON is needed.
