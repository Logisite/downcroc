# 1.3.2.post7

Follow-up fixes for the Gmail thread id backfill.

## What changed

- Holes sent through the Gmail API already store the provider message id. When the
  RFC Message-ID search finds nothing for one of them, backfill now calls
  `messages.get(id, format="minimal")` and writes the returned `threadId` before
  recording a strike. `backfill.resolved` reports `medium="provider"` for these.
- The IMAP Sent-folder sweep is now cached for the whole pass instead of repeating on
  every drain turn. Large Sent folders are no longer rescanned every few minutes.
- The exact lookup prevents API-sent holes from being marked missing after the retry
  window even though Gmail still has the message.

## What you should see

After upgrading and restarting the daemon, the first drain turn should resolve both
SMTP-sent holes found by the IMAP sweep and Gmail-API-sent holes found by the stored
provider id. `backfill.imap_swept` should appear once per account per pass, not once per
drain turn.
