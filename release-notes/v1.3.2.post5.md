# 1.3.2.post5

Recovers Gmail thread ids for older sent mail so follow-ups and inbound replies
join the right conversation. The backfill runs in the background and needs no
user action.

## What this changes

- **Automatic thread id backfill.** A background worker finds sent attempts that
  have an outgoing `Message-ID` but no provider thread id, and fills the hole
  from your Gmail Sent folder. It sweeps Sent over IMAP first (`X-GM-THRID`, a
  readonly `BODY.PEEK` fetch, zero API units), then falls back to a per-message
  Gmail API search. IMAP thread ids are converted to the same lowercase hex
  form the API returns, so all four paths (API send, SMTP send, IMAP recovery,
  API recovery) store byte-identical values.
- **Safe and conservative.** Ambiguous matches write nothing, repeated misses
  are marked missing only after a cooldown, calls and passes are paced with
  jitter, and errors back off instead of stopping the daemon. An already-filled
  hole is never overwritten.
- **Configurable.** New `backfill.*` settings control the worker (enable, lane
  counts, concurrency, pacing, retries, IMAP sweep thresholds). See
  `downcroc config schema` and the config reference in the book.
- **Observable.** Ten `backfill.*` log events cover pass lifecycle, lookups,
  and delays. Filter with `downcroc logs --event backfill.`.

## Why it matters

Follow-up sends and inbound attribution resolve a reply's Gmail conversation
from the stored provider thread id. Mail sent before thread id capture was
introduced carried no id, so replies started new threads. Once the backfill has
filled those rows, follow-ups and inbound matching work for older mail too.

## Notes

- The backfill needs a working Gmail connection on the affected accounts; it
  skips accounts it cannot authenticate or reach and retries on later passes.
- This release also updates the config reference and log event reference for
  the new settings and events.
