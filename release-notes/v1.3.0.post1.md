## Automatic sending now shows up in your stats again

Auto-routed jobs deliberately do not store a mailbox on the job row. The mailbox
is chosen at send time, so the only record of who actually sent a message lives
in the send attempt. The activity rebuild was reading the empty job row anyway,
which caused two visible problems:

- `downcroc stats rebuild` failed with `NOT NULL constraint failed:
  activity_daily.account_id`.
- `downcroc mail prune --yes` deleted the old self-copies, then returned
  `Internal Server Error` while rebuilding stats. The cleanup had already
  happened, but the command looked like it failed.

The rebuild now resolves each job's account from its latest send attempt when
the job has no pinned account. Jobs with no account anywhere are skipped instead
of breaking the rebuild.

**What you can do now:** `downcroc stats rebuild` works on mailboxes that use
automatic routing, and `downcroc stats summary` attributes those sends to the
account that carried them.

## Cleanup no longer fails after it succeeds

`downcroc mail prune` now reports the prune result even if the follow-up counter
rebuild fails. The JSON response includes `stats_rebuilt`, and the human output
tells you to run `downcroc stats rebuild` instead of showing a server error
after the messages are already gone.

**What you can do now:** run `downcroc mail prune --dry-run`, then
`downcroc mail prune --yes`, and trust the result you see.

## Single jobs can be created and sent again

`downcroc job create` and `downcroc job send` referenced a manual-compose helper
that was never connected to the outbound service. The result was an unhandled
`AttributeError: 'OutboundService' object has no attribute '_manual'`.

The helper is now wired in at startup. One-off jobs are composed and routed the
same way as batch jobs.

**What you can do now:** create a single job and send it immediately, without
building a campaign first.

## Upgrade notes

- No database migration is required.
- No configuration changes are required.
- Existing activity rows are not rewritten automatically. Run
  `downcroc stats rebuild` once after upgrading if your counters were affected
  by the failed rebuilds.
