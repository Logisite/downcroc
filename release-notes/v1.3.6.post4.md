# 1.3.6.post4

Fixes immediate follow-up creation for auto-routed campaigns, corrects interactive
picker ordering, and removes the expensive ETA work that made batch pickers slow.

## Immediate follow-ups with unassigned parent jobs

Immediate follow-up creation crashed with a `TypeError` when parent jobs had
`account_id = NULL`, which happens with auto-routed or unpinned campaigns. The
sync helper sorted a set of account ids before its `None` guard, so Python had
to compare `None` with a string.

The helper now filters out `None` before sorting. `POST /api/batches/{id}/followups`
no longer fails for these campaigns, and the planned `followups declare` path
remains unchanged.

This is a crash fix only. It does not backfill account ids on already sent
jobs, and it does not try to resolve the actual sending account for the sync.
Sent jobs remain outside the reassignment path, as before.

## Interactive picker ordering

The batch, job, and failed-job value resolvers now pass
`newest_first = [cli] list_order` to the API. The batch approve picker starts
with the newest batch, so you no longer have to scroll to the bottom to reach
recent work.

## Faster batch picker

`GET /api/batches` accepts `include_eta=false`. The interactive batch picker
uses it, so it no longer computes a pending ETA for every batch before showing
the list. The picker gets ids, names, states, counts, and creation times
without the expensive per-batch work.

Normal `downcroc batch list` and API callers still get ETA by default. This is
an additive query parameter and does not change the API contract.

## What you should see

- `downcroc batch followup <batch> payload.json --step fu1` works on campaigns
  whose sent jobs have no pinned account.
- In the interactive tree, the batch picker opens with the newest batch.
- The picker appears quickly even with many batches.

## Acceptance

Relevant tests pass for the touched paths. Ruff, format, docs map, glossary,
lock, and compileall pass. One pre-existing race in
`test_cancel_reports_what_was_already_sent` still fails with and without these
changes; it is unrelated to this release.
