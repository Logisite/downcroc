# 1.3.3

Backfill now searches Trash before calling a hole missing, and tells you why any hole
is still open.

## What changed

- The API lookup searches Sent first, then anywhere including Spam and Trash. The second
  search is only spent when Sent is empty. Messages you moved to Trash are recovered on
  the next pass instead of waiting days for a strike.
- "Not found" is decided by evidence, not by a 7-day wait. A full-scope search that
  finds nothing marks the hole `missing` once `backfill.settle_s` (default 15 minutes)
  has passed since the send, which covers Gmail search indexing.
- Lookup errors no longer mean "missing". A hole whose checks keep failing becomes
  `unresolved`, a separate terminal state, after `retry_after_days`. Reconnect the
  account, then retry.
- New `downcroc backfill` command: `status` shows holes per account and why each account
  is blocked (for example `needs_reauth`), `explain` shows one hole's evidence, and
  `retry` reopens a hole into the next pass. The same surface is on the API under
  `/api/backfill`.
- New log events: `backfill.hole_checked` records the evidence of every lookup
  (scopes, hit counts, provider result), `backfill.retry_scheduled` records a next check
  time, and `backfill.unresolved` records the terminal could-not-check mark.
  `backfill.resolved` and `backfill.missing` now carry the search scope and evidence.
- Reconnecting an account (or it falling into `needs_reauth`) wakes backfill immediately,
  so its holes are checked without waiting for the hourly re-check.
- New `[backfill]` settings: `settle_s`, `retry_base_s`, `retry_max_s`.
  `retry_after_days` is now the cap for repeated errors only.
- Progress columns on `send_attempts` track every hole's checks. Old rows with null
  columns are treated as due, so existing holes are picked up on the first pass after
  the upgrade.

## What you should see

After upgrading, the four holes that sat in Trash fill within one pass. Holes Gmail
truly no longer has go `missing` quickly instead of after 7 days, and holes that could
not be checked show as `unresolved` with the cause. `downcroc backfill status` should
match what the log says, with `blocked_accounts` naming the `needs_reauth` account.
Log lines now also show your computer's local time by default; pass `--utc` to
`downcroc logs` for UTC, and `--since` accepts naive timestamps as local time.
