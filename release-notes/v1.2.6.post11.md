## Your inbox is your inbox again

Downcroc now keeps Gmail inbox ingestion separate from your sent mail.

Before this release, the Gmail API backfill and completeness sweep also read the
`SENT` label, then stored every result as `INBOX`. On a busy mailbox that turned
`downcroc mail list` into a copy of your outbox: the last 585 "inbox" rows in a
live mailbox were 525 copies of the account's own sent campaigns. Bounces and
real replies were buried underneath them.

Now:

- Gmail history watches `INBOX` only.
- The backfill searches `in:inbox` only.
- The Gmail completeness sweep searches `in:inbox` only.
- Messages from other labels are not silently rewritten as inbox mail.

**What you can do now:** `downcroc mail list` shows mail that actually arrived in
the inbox, and `downcroc mail threads` reflects conversations rather than
outbound copies.

### Clean up mail that was already imported

There is a new command for the rows created before this fix:

```bash
downcroc mail prune --dry-run
downcroc mail prune --yes
```

It removes only stored inbox rows that are from one of your own account
addresses, have no attributed job, are not bounces, and have no reply state.
`--dry-run` reports the count and bytes without deleting anything. After a real
prune, activity counters are rebuilt from the remaining data.

## First import starts when you started

New configuration:

```toml
[inbound]
ingest_since_init = true
```

This is the default. Downcroc records the first initialization time once, then
ignores mail dated before it when an account is first connected or when the
Gmail API backfill runs. A daemon started today no longer imports the previous
week or month of history just because the mailbox has it. Messages from the same
second as initialization are kept.

If you deliberately want the old behaviour, set it to `false` and use the
existing lookback settings:

```bash
downcroc config set inbound.ingest_since_init false
downcroc config set inbound.initial_sync_days 30
```

**What you can do now:** start with a clean slate, or opt in to history on the
mailboxes where you actually want it.

## Replies are found more reliably

The classifier no longer depends only on one subject spelling or exact headers.

- Subject prefixes are stripped repeatedly and case-insensitively, including
  `Re:`, `Fwd:`, `AW:`, `SV:`, `Antw:`, localized variants, and auto-reply
  prefixes such as `Out of Office Re:` and `Automatic reply:`.
- `sent_unconfirmed` jobs can now receive a reply, not only `sent` jobs.
- When a provider rewrites the RFC `Message-ID` (Gmail commonly does for
  Gmail API sends), a reply-shaped message now falls back to the sender and the
  most recent matching job inside the reply window. It is marked `probable`
  with method `participant`, rather than dropped as `none`.
- Auto-replies are detected through the RFC 3834 `Auto-Submitted` header,
  `X-Autoreply`/`X-Autorespond`, and `Precedence: auto_reply` — not through
  fragile body text matching.

**What you can do now:** `downcroc mail list --reply-state probable` and
`downcroc mail threads` show likely replies whose headers did not survive the
provider. Confirmed replies still require a header match; probable replies do
not suppress the address automatically.

## Automatic replies are no longer counted as bounces

An out-of-office reply often has `Return-Path: <>`. The old DSN check treated
that alone as a delivery failure, so vacation replies appeared as bounces. DSN
detection now requires a delivery-status body part, a `multipart/report` with
`report-type=delivery-status`, a known mailer-daemon/postmaster sender, or a
mailer-daemon sender with a delivery-failure subject.

**What you can do now:** `downcroc failed` and bounce counts stay reserved for
real delivery failures, while auto-replies show up in the reply classifier.

## Quota logs tell you what is left

`quota.committed` and `quota.reserved` now include `limit` and `remaining`:

```text
quota.committed account=acct_... day=2026-11-04 used=39 reserved=0 limit=100 remaining=61
```

**What you can do now:** watch the remaining allowance directly in
`downcroc logs --event quota.` instead of calculating it from `used`.

## Upgrade notes

- The database migration adds an `initialized_at` timestamp to the existing
  runtime state. Existing installations backfill it from the oldest account's
  creation time; fresh installations record it when the daemon first starts.
- `downcroc mail prune` is safe to dry-run first and is the recommended way to
  clear old self-copies after upgrading.
- No new Python dependency is required. Reply detection uses the standard
  `email` headers and the existing message store; the third-party
  `email-reply-parser` packages only strip quoted text and do not classify
  whether a message answers a job, so adding one would not solve this.
