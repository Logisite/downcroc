# 1.3.6.post3

Unblocks event-driven extensions. Enablement now survives reloads, published
events reach running subscribers, multi-round extensions can be tested, and
quota events carry the numbers an extension needs. This post also bundles the
capability documentation and CLI fixes from the previous working-tree commit.

## Extension enablement

Enable state is now authoritative in `extension_state` once an extension has
been enabled. A `[extensions.<id>].enabled` config value is only the initial
value for a new extension. Adding another artifact or reloading the host no
longer turns a running extension off.

`downcroc extension list` and `show` now include a `reason` field. When an
extension is not running, it says why: `disabled`, `config_disabled`,
`artifact_invalid`, `approval_required`, `crashed`, or `not_started`.

## Event injection and bus delivery

`event.publish` from a one-shot extension now reaches running subscribers
through the daemon event bus. Added a deterministic injection path:

```sh
downcroc extension inject watcher \
  --event quota.committed \
  --payload '{"account":"acct_1","used":30,"limit":50,"remaining":20,"day":"2026-11-24"}'
```

The payload is sanitized the same way as daemon events. This gives extension
authors a supported way to test event-driven behavior without waiting for real
mail or quota activity.

## Multi-round protocol

The host now supports repeated `actions -> result` exchanges for one event.
This makes the reply-bot example in the authoring guide valid: an extension can
read a `kv.get` result, send a reply, and store state in the same event.

- `extensions.max_protocol_rounds` defaults to 8.
- `downcroc extension test ID --rounds N` allows N rounds, default 1.
- An empty `actions` list ends the event.
- `protocol.md` and `authoring.md` document the loop.

## Quota visibility

`SAFE_FIELDS` now keeps `used`, `reserved`, `remaining`, `limit`, and `day`, so
a `quota.committed` bus event carries the counters. An extension no longer has
to parse the JSONL log to detect an exhausted allowance.

`quota.get` now returns `account`, `day`, `limit`, `used`, `reserved`, and
`remaining`. `remaining` is `max(0, limit - used - reserved)`. The capability
and protocol docs describe the fields.

## Desktop notifications

`notify.system` is now registered and documented. It is elevated and requires
approval. The command comes from config:

```toml
[extensions]
notifier = ["notify-send"]
```

The title and message are appended as arguments. No shell is used. If no
notifier is configured, the capability returns `ok: false` with
`error: notify_unavailable`. The old `notify` capability still writes a log
event only.

## Bundled documentation and CLI fixes

The previous working-tree commit is included:

- `extension capabilities --json` returns each capability with its tier, and
  the table view shows a tier column.
- `capability.list` and the CLI now agree.
- `capabilities.md` documents every registered capability. The docs linter now
  checks this automatically.
- Log versus bus event behavior is documented. `extension.*` events are
  log-only; `quota.committed` and a few other daemon events are also bus
  events.

## Compatibility

Existing manifests and artifacts keep working. Enablement changes only affect
extensions with no explicit `[extensions.<id>].enabled` config. Multi-round
behavior is opt-in for `extension test` through `--rounds`; running extensions
gain the loop automatically within the configured maximum.

## Acceptance

Twelve extension black-box tests pass, including enable persistence, published
event delivery, multi-round testing, quota counters, capability tiers, denial
and approval, reply sending, and artifact verification. Config schema, review
ordering, ruff, format, docs map, glossary, lock, and compileall all pass.
