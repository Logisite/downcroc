# 1.3.5.post2

List commands now show the newest rows first by default. Config and a CLI flag
can put the oldest rows first instead.

## What changed

`batch list`, `job list`, `failed list`, `mail list`, and `mail threads` default
to newest first. The newest row is now the first row, and `--limit`/`--offset`
select the newest page.

Two ways to get the old order:

- Set `[cli] list_order = "oldest_first"` in `config.toml` to change the default
  for every list command.
- Pass `--oldest-first` on a single command.

`--newest-first` is still accepted as the explicit form of the default. The two
flags are mutually exclusive, and either one wins over config.

Logs and stats keep their own ordering. Account lists, template lists, and
`followups due` are unchanged because they are not newest/oldest queues.

## What you should see

Run `downcroc batch list` and the most recently created batch is the first row.
Add `--oldest-first` and the oldest batch is first. Set the config key and every
list command starts with the oldest row, until you pass `--newest-first` for a
single run. JSON output follows the same order.

`mail threads` uses a new optional API query parameter for this, so the daemon
must be running this release for `--oldest-first` to change that listing. The
daemon keeps its existing default when the parameter is absent.
