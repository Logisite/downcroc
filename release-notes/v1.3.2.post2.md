# 1.3.2.post2

`1.3.2.post2` fixes Gmail API follow-up threading so replies stay in the original conversation.

## Fixes

- **Gmail API reply threading:** Follow-up messages sent through the Gmail API now include the provider `threadId` on `messages.send` (in addition to MIME reply headers), so replies are threaded with the original conversation instead of being sent as separate messages.
- **Provider thread tracking:** Gmail API sends now record the returned provider thread id on send attempts, allowing later follow-up steps in the same chain to resolve and reuse the correct Gmail thread.
- **Gmail API sweep attribution:** Inbound Gmail API messages can now be attributed by matching the Gmail `threadId` to a previously sent attempt in that account/thread, giving sweeps a direct thread signal alongside header and subject matching.

## Upgrade notes

- This release includes a database migration that adds `send_attempts.provider_thread_id`. The daemon runs migrations at startup.
- Restart the daemon/service after upgrading to load the updated behavior.
- Existing send attempts do not gain historical provider thread ids retroactively; new Gmail API sends and follow-ups will capture and thread correctly going forward.
