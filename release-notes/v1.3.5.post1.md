# 1.3.5.post1

Global table flags work when placed before the command, not only after it, and
the GitHub update check now runs at most once a day by default.

## What changed

`--stack`, `--grid`, and `--addresses` are global flags, but the subcommand
parser gave each of them its own `False` default. When the flag appeared before
the command, argparse copied the subcommand's default over the value the root
parser had just set. The flag was silently ignored.

The subcommand definitions now suppress those defaults, so the root parser's
value survives. The flags behave the same whether you write them before or
after the command.

The cached GitHub update check also has a new default interval of `86400`
seconds (one day), up from `3600`. `cli.update_check_interval_s` still controls
it if you want a different cadence.

## What you should see

This command now stacks the fields instead of drawing a boxed table:

```sh
downcroc --stack --glyphs nerd --color always batch list --parents
```

The same applies to `downcroc --grid batch list` and
`downcroc --addresses stats accounts`. Interactive tree runs are unchanged:
the option editor already appends these flags to the command it runs. The
update footer now appears at most once a day unless you lower
`cli.update_check_interval_s`. No configuration change is required.
