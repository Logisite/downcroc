# 1.3.2.post4

Follow-up to the install self-healing release: it fixes three defects found
while recovering a real machine after a Python upgrade and a restore, and
adds the repair page to the book.

## Fixes

- **Restore keeps your managed install working.** A restore bundle never
  contains the managed virtual environment, but a restore swapped the whole
  data directory - including the venv inside it - aside. The `downcroc`
  launcher was left dangling after every successful restore. Restore now
  moves the venv back into place after the swap. On a fresh machine with no
  managed install yet, run the install script once after restoring.
- **Restore no longer leaves an empty backup directory.** When the data
  directory existed but held no database (for example after a wipe), restore
  still moved it aside as `downcroc.bak-<timestamp>`. It now only preserves
  a backup when the directory actually holds live data.
- **The health probe no longer rejects healthy installs.** The import check
  launched the interpreter through its resolved system path, so the venv's
  site-packages never loaded and every managed install read as
  `needs_reinstall`. The probe now launches the venv's own `python` link.
- **install.sh resolves the interpreter through PATH.** The interpreter was
  passed through `realpath` as a bare name such as `python3`, which
  resolved against the install working directory and pinned the venv links
  to a nonexistent path.

## Docs

- New command page for `downcroc repair` in Part II.
- New glossary terms: repair, managed install, venv, interpreter links,
  site-packages.
- Log event reference now documents `db.revision_ok`, `db.migrate_failed`,
  and the expanded `daemon.start_failed` fields.
